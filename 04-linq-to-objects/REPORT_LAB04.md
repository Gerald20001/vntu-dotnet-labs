## 2. Завдання варіанта №1
- **Модель даних:** `record Student(string Name, string Group, int Score)` (25 записів, 4 різні академічні групи: ПЗ-21, ПЗ-22, КН-21, ІПЗ-21).
  Додаткова колекція для `Join`: `record GroupCurator(string Group, string CuratorName, string Department)`.
- **Обов'язкові запити:**
  1. Середній бал за кожною групою (`GroupBy` + `Average`), відсортований за спаданням рейтингу.
  2. Топ-5 студентів за оцінкою по всій вибірці (`OrderByDescending` + `Take(5)`).
  3. Розподіл кількості студентів за діапазонами оцінок («відмінно» 90+, «добре» 75–89, «задовільно» 60–74, «незадовільно» <60) — групування за обчислюваним ключем-діапазоном.
  4. Перевірка через `All`, чи всі студенти заданої групи (вводиться з консолі) мають оцінку не нижче заданого порогу.
  5. Перевірка через `Any`, чи є в заданій групі відмінники (бал $\ge 90$).
  6. Фільтрація та сортування з проєктуванням в анонімний тип (`Where` + `OrderByDescending` + `ThenBy` + `Select`).
  7. З'єднання двох колекцій (`Join`) між студентами та кураторами їхніх груп.
  8. Агрегатні підсумки по всій вибірці (`Count`, `Min`, `Max`, `Average`, `Sum`).
  9. Порівняння запитів у Method-синтаксисі та Query-синтаксисі (`from...group...by...select`).
- **Збереження у файл:** Експорт підсумкової статистики за групами у CSV-файл `students_report.csv` за допомогою `File.WriteAllLines`.
- **Граничний випадок:** Користувач вводить групу, якої немає серед даних — запит виводить зрозуміле повідомлення «Групу не знайдено» замість винятку або некоректної відповіді.

## 4. Порівняння Method-синтаксису та Query-синтаксису

```csharp
// 1. Method Syntax (методи розширення та лямбди)
var methodResult = students
    .GroupBy(s => s.Group)
    .Select(g => new { Group = g.Key, Avg = g.Average(s => s.Score) })
    .OrderByDescending(x => x.Avg);

// 2. Query Syntax (декларативний SQL-подібний вираз)
var queryResult = from s in students
                  group s by s.Group into g
                  orderby g.Average(x => x.Score) descending
                  select new { Group = g.Key, Avg = g.Average(x => x.Score) };
```

## 7. Відповіді на контрольні питання

**1. У чому різниця між відкладеним (deferred) та негайним (immediate) виконанням LINQ-запиту? Наведіть приклад, коли це має значення.**  
*Відповідь:* Більшість операторів LINQ (`Where`, `Select`, `OrderBy`, `GroupBy`) повертають `IEnumerable<T>` і виконуються **відкладено** — запит фактично обчислюється лише в момент ітерації (`foreach`). Оператори негайного виконання (`ToList()`, `ToArray()`, `Count()`, `Average()`, `First()`) обчислюють результат одразу та кешують його в пам'яті. Це критично, коли вихідна колекція змінюється після створення запиту: відкладений запит побачить нові дані, а негайний — лише ті, що були на момент виклику `ToList()`.

**2. Чим `Select` відрізняється від `SelectMany`?**  
*Відповідь:* `Select` виконує проєкцію 1-до-1: для кожного елемента повертає рівно один новий елемент (якщо елемент містить список, повернеться послідовність списків `IEnumerable<List<T>>`). `SelectMany` виконує сплощення (flattening) 1-до-багатьох: розгортає всі вкладені колекції в єдиний плаский потік елементів `IEnumerable<T>`.

**3. Як реалізується групування (`GroupBy`) і які структури даних воно повертає?**  
*Відповідь:* `GroupBy` повертає послідовність об'єктів `IEnumerable<IGrouping<TKey, TElement>>`. Кожна група реалізує інтерфейс `IGrouping`, що містить властивість `Key` (ключ групування) і сама є перелічуваною послідовністю елементів, які мають даний ключ.

**4. У чому різниця між `Join` та `GroupJoin`?**  
*Відповідь:* `Join` виконує плоске з'єднання (еквівалент SQL `INNER JOIN`): для кожного збігу створюється окрема пара елементів. `GroupJoin` виконує ієрархічне з'єднання (еквівалент `LEFT OUTER JOIN` з групуванням): для кожного елемента першої колекції повертається сам елемент і ціла колекція відповідних йому елементів другої колекції.

**5. Які є переваги та недоліки query-синтаксису порівняно з методним синтаксисом LINQ?**  
*Відповідь:*
- **Query Syntax:** Перевага — легка читабельність для складних запитів із багатьма з'єднаннями (`join`), групуванням (`group by into`) та підзапитами завдяки подібності до SQL. Недолік — підтримує не всі оператори LINQ (наприклад, `Take`, `Skip`, `Distinct`, `Count` вимагають обгортання у дужки або методний синтаксис).
- **Method Syntax:** Перевага — повний доступ до всіх операторів послідовностей .NET, лаконічність у простих вибірках (`Where(...)`). Недолік — менша наочність при багаторівневих `join`.
